## `ui-audit.mjs --path=/cv` — premier run complet (10 combinaisons)

0 overflow horizontal, 0 violation axe-core (mobile-390 + laptop-1440, EN et
FR), 0 erreur console/page sur les 10 combinaisons.

**CLS mesuré — anomalie isolée et confirmée** :

| combo | CLS |
| --- | --- |
| mobile-390 EN | 0.0003 |
| tablet-768 EN | 0.0007 |
| laptop-1440 EN | 0.0004 |
| desktop-1920 EN | 0.0002 |
| mobile-390 FR | 0.0079 |
| **tablet-768 FR** | **0.1603** |
| laptop-1440 FR | 0.0005 |
| desktop-1920 FR | 0.0002 |
| laptop-1440 EN reduced-motion | 0.0122 |
| laptop-1440 FR reduced-motion | 0.0102 |

Une seule combinaison sort du bruit : **tablet-768 + FR**, à 0.16 — dans la
zone « needs improvement » de Core Web Vitals (seuil 0.1), un ordre de
grandeur au-dessus des neuf autres combinaisons. Investigué avant de le tenir
pour un défaut réel (leçon cycle 021 : ne pas croire un chiffre isolé sans le
creuser) :

- **Reproductible à 100 %** (sonde ad hoc, 4 runs indépendants, `PerformanceObserver`
  bufferisé) : CLS = 0.1598-0.1603 à chaque fois, deux entrées de shift
  identiques à chaque run — un shift de 0.1557 impliquant `.cv-section`, un
  `LI` (timeline), `.cv-hook`, `.cv-contacts`, plus un nœud non identifié, et un
  second de 0.0041-0.0046 sur `.cv-timeline-bullets`.
- **Bisection de largeur** (`lang=fr` fixe) : 768px → 0.1603, 767px → 0.1596,
  700px → 0.0047, 640px → 0.0005. Bande étroite ~700-768px, uniquement en FR
  (768px EN → 0.0007). Le texte français, plus long à largeur de police
  identique, franchit une limite de retour à la ligne à cette largeur que
  l'anglais ne franchit pas.
- **Cause confirmée par élimination du cache** : même page, même viewport,
  même langue, un `page.reload()` dans le même contexte (polices déjà en
  cache navigateur) → **CLS = 0**, contre 0.1603 au premier chargement à froid.
  C'est la signature exacte d'un reflow de police web (FOUT — le texte
  s'affiche d'abord dans la police de repli du système, puis se redessine avec
  la vraie police une fois chargée, avec des métriques différentes qui
  déplacent les retours à la ligne).
- **Cause racine identifiée dans le code** : `index.html` charge Almarai/
  Fraunces/Instrument Serif/JetBrains Mono via une seule URL Google Fonts avec
  `&display=swap` — un seul paramètre `display` pour les quatre familles, donc
  pas de réglage par police sans scinder la requête. `body` (src/index.css:59)
  utilise `"Almarai", -apple-system, ... sans-serif` comme pile de base ; c'est
  elle qui est en cause ici (le contenu affecté — hook, timeline, contacts —
  est du texte courant en police de base, pas un titre en Fraunces).
- **Écart doc/code repéré au passage, non traité ce cycle** : MISSION-UI.md §1
  documente l'identité comme « Fraunces (titres), JetBrains Mono (technique),
  **Inter** (corps) ». Le code déclare `--font-body: "Inter", system-ui,
  sans-serif` dans `tokens.css` mais **ce token n'est référencé nulle part**
  (`grep -rn "var(--font-body)" src/` → 0 résultat) et Inter n'est jamais
  chargé (absent de l'URL Google Fonts). La police de corps réellement
  utilisée depuis l'origine du projet est **Almarai**. Sans savoir si c'est un
  choix délibéré jamais reporté dans la doc, ou un token orphelin d'une
  migration jamais terminée, je ne corrige ni le code ni la doc à l'aveugle —
  question consignée dans `QUESTIONS.md` (Q5), parce que la réponse détermine
  la bonne façon de corriger le CLS (ajuster le chargement d'Almarai en place,
  ou finir la migration vers Inter).

**Pas de correctif livré ce cycle sur ce point.** La correction standard
(`font-display: optional` sur la police de corps, ou des descripteurs
`size-adjust`/`ascent-override` calibrés sur la police de repli) touche le
chargement de police de **tout le site**, pas seulement `/cv` — un chantier
qui exige sa propre vérification avant/après sur les 4 viewports × 2 langues
des **deux** routes, pas une correction que je greffe en fin d'un cycle déjà
consacré à l'outillage. Consigné en P1 dans `BACKLOG.md` avec la reproduction
exacte ci-dessus, pour qu'un futur cycle n'ait pas à re-creuser.
