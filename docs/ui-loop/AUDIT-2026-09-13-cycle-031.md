## Constat — P1/P0 de crédibilité : page fantôme accessible par URL directe

En lisant `DeepDivePage.tsx` (jamais audité jusqu'ici, signalé comme angle
mort par le cycle 030), la première question est : **qui appelle cette
page ?** `grep -rn "projet/"` sur tout `src/` ne retourne que la définition
de la route dans `App.tsx` et l'auto-référence de `DeepDivePage.tsx` vers le
« projet suivant ». **Aucun élément de l'interface — carte, lien, nav — ne
mène jamais vers `/projet/:slug`.** La page est du code mort qui répond
`200` (vérifié par un serveur `vite` local + Playwright), pas du code
inaccessible : un visiteur qui devine ou reçoit l'URL l'atteint réellement.

Ce que cette page montre une fois atteinte (capture prise avant suppression,
`1440`, `/projet/jobtrackr`) :
- **Texte 100 % français, sans variante EN**, alors que le sélecteur de
  langue global (rendu par `App.tsx` en dehors de `<Routes>`) reste visible
  et cliquable sur cette page — violation directe de MISSION-UI.md §1
  (« Toute section... doit exister dans les deux langues, sans texte
  orphelin »).
- Des chiffres différents de la carte réelle JobTrackr de la page d'accueil
  (`src/data/projects.ts`, id `02`) : cette page fantôme vient d'un modèle de
  données concurrent (`src/content/projects.ts`), jamais synchronisé avec le
  modèle réellement utilisé partout ailleurs.
- Un encadré visuel cassé autour du titre `<h1>` (bordure carrée parasite,
  cause non investiguée puisque le composant est supprimé plutôt que réparé).

**Cause racine** : un premier jet de système de page de détail
(`content/projects.ts`, `content/deepdives.ts` + `content/deepdives.md`,
`content/projets.md`, `sections/DeepDive.tsx`, `pages/DeepDivePage.tsx`,
`components/ProjectCard.tsx`, `FictifTag.tsx`, `LazyMediaSlot.tsx`),
antérieur au système actuel (`data/projects.ts` + `ProjectDetailModal.tsx`
branché depuis `OnePage.tsx`), jamais retiré quand le second a pris le
relais. Exactement le même schéma que le cluster supprimé au cycle 015
(`sections/{Hero,Nav,About,Contact,Stack,Manifeste,FlowProjets}.tsx`), sauf
que celui-ci était resté invisible plus longtemps car `DeepDivePage.tsx`
apparaissait « utilisé » dans la table de routes de `App.tsx` — une lecture
du seul routeur, sans vérifier qui clique le lien, masquait le fait qu'il
s'agissait de code mort.

**Vérification exhaustive avant suppression** (pas de suppression sur
impression) : pour chacun des 9 fichiers du cluster, `grep -rln` sur tout le
repo (hors `node_modules`) ne retourne que des références internes au
cluster lui-même. Les tokens CSS `--fictif-ink`/`--fictif-border`
(`tokens.css`, `index.css`) ne sont consommés que par `FictifTag.tsx` (donc
également morts) mais laissés en place : leur retrait est hors périmètre de
ce chantier (aucune classe Tailwind vivante ne les utilise, aucun risque,
mais aucun bénéfice mesuré à les toucher aujourd'hui).

**Décision** : suppression complète du cluster plutôt que réparation, parce
que (1) rien ne le rend jamais atteignable depuis l'interface, (2) le
modèle de données qu'il porte est obsolète et divergent du modèle réel, (3)
le réparer (ajouter l'i18n, corriger la bordure, resynchroniser les chiffres)
dépenserait un chantier entier sur une page que personne ne peut trouver.
