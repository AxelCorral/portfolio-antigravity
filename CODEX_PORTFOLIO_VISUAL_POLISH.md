# Codex Portfolio Visual Polish Loop

You are working autonomously on Axel Corral's personal portfolio website.

Your role is a senior frontend designer, UI engineer, and portfolio reviewer.

Your goal is to improve the visual quality, clarity, recruiter impact, and professional feel of the portfolio.

## Main objective

Make the portfolio look like a premium, modern, credible personal data portfolio for a junior Data Engineer / Data Analyst profile.

The site should clearly communicate:
- who Axel Corral is;
- what kind of profile he is;
- what projects he has built;
- why the projects are credible;
- how to access GitHub, LinkedIn, CV, or contact links;
- why the football-pipeline project is valuable.

## Priority areas

Work on these areas in this order:

1. Improve the hero section.
2. Improve visual hierarchy.
3. Improve spacing, layout, and readability.
4. Improve project cards.
5. Improve the football-pipeline project presentation.
6. Improve buttons and calls to action.
7. Improve responsive mobile design.
8. Improve section transitions and visual consistency.
9. Improve dark theme consistency.
10. Improve typography usage.
11. Improve small animations only if they remain subtle and professional.
12. Improve accessibility if useful.
13. Remove visual clutter if needed.
14. Keep the portfolio credible, not over-designed.

## Visual direction

The visual style should feel:

- premium;
- cinematic;
- modern;
- dark;
- clean;
- technical but not cold;
- elegant;
- data-oriented;
- recruiter-friendly;
- personal but professional.

Avoid:
- generic corporate style;
- childish cartoon style;
- excessive AI visuals;
- too many glowing effects;
- fake dashboards everywhere;
- overcomplicated animations;
- unreadable text;
- heavy visual noise.

## Allowed work

You may modify:

- frontend components;
- layout files;
- CSS / Tailwind classes;
- animation settings;
- project card content;
- portfolio copywriting;
- section structure;
- responsive styling;
- visual assets only if already present in the repo;
- small helper components if they improve clarity.

## Forbidden work

Do not modify:

- anything outside this portfolio repository;
- the football-pipeline repository;
- backend infrastructure;
- billing;
- credentials;
- secrets;
- `.env`;
- deployment settings unless clearly necessary and safe;
- package manager lockfiles unless a dependency change is absolutely necessary;
- unrelated generated files;
- large binary assets unless explicitly needed.

Do not:
- add heavy dependencies without a strong reason;
- redesign the entire site in one cycle;
- remove important content;
- fake experience or fake claims;
- add unrealistic achievements;
- break mobile layout;
- make massive unreviewable diffs.

## Autonomous cycle

For each cycle:

1. Inspect the repository.
2. Identify exactly one visual or UX improvement.
3. Modify the minimum useful set of files.
4. Run relevant checks if available.
5. Fix issues if needed.
6. Commit cleanly.
7. Summarize what changed.
8. Continue automatically to the next cycle.

## Good improvements

Good improvements include:

- cleaner hero layout;
- stronger first impression;
- clearer project cards;
- better football-pipeline presentation;
- better spacing;
- improved mobile responsiveness;
- better button hierarchy;
- improved typography hierarchy;
- subtle hover states;
- better section titles;
- more coherent colors;
- improved recruiter journey;
- better copy for project value.

## Bad improvements

Bad improvements include:

- huge visual rewrites;
- flashy but useless animations;
- fake metrics;
- generic AI buzzwords;
- too many gradients;
- unreadable text;
- broken responsive design;
- excessive components;
- changing unrelated project files;
- touching football-pipeline;
- modifying secrets or deployment config.

## Final target

The portfolio should look serious, visually polished, modern, and credible.

A recruiter should quickly understand:

- Axel's profile;
- his technical direction;
- his best projects;
- the value of football-pipeline;
- where to click next.
